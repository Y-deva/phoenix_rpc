# Архитектура Phoenix Wallet GUI

## Поток данных

```text
+-------------+      JSON-RPC       +-------------+      PyQt6       +-----------+
|  novacoind  | <-----------------> |   main.py   | <--------------> |   GUI     |
|    (C++)    |   HTTP, basic auth  |   (Flask)   |   HTTP, basic    |  (this)   |
+-------------+                     +-------------+      auth        +-----------+
                                           |
                                    wallets.db, keychain,
                                    utxo_parser, signrawtransaction
```

GUI не обращается к `novacoind` напрямую. Прокси скрывает Falcon-подписи,
P2SH-адреса и SQLite-индекс. Такой маршрут позволяет запускать интерфейс в
отдельном виртуальном окружении без `liboqs` и `gostcrypto`.

## Слои

### `phoenix_gui/rpc`

- `RPCClient` - минимальный JSON-RPC 1.0 клиент. Одна HTTP-сессия на поток,
  basic auth, таймауты, понятные исключения. Параметр `transport` позволяет
  тестировать сервис без сети.
- `models.py` - неизменяемые dataclass-модели ответов. Деньги хранятся в
  `Decimal`.
- `WalletService` - прикладные операции: баланс, адреса, история, UTXO,
  создание и подпись raw-транзакций, а также `pstore`, `pload` и `pcancel`
  для публичного хранилища. Баланс считается из `listunspent`, а не только из
  `getbalance`, потому что `getbalance` включает неподтвержденные входы.

### `phoenix_gui/core`

- `coinselect.py` повторяет правила `unlock.py`: 1800 байт на вход, 34 байта
  на P2PKH-выход, 15 байт на OP_RETURN. Экспертный режим передает выбранные
  UTXO в `fixed_inputs`.
- `daemon.py` запускает `novacoind` через `QProcess` в foreground-режиме.
  Демон не становится сиротой при закрытии окна. Если порт уже занят,
  процесс помечается внешним.
- `media.py` рисует абстрактный фон, если файл не выбран, или показывает
  локальное изображение/видео. Затемнение и размытие применяются поверх.
- `tasks.py` выполняет RPC в `QThreadPool`; сигналы доставляются в GUI-поток,
  поэтому виджеты не трогаются из рабочих потоков.
- `sync.py` объединяет высоту блоков демона и файлы прогресса
  `utxo_parser.py`.

### `phoenix_gui/i18n`

- `TranslationManager` читает JSON-каталоги из `phoenix_gui/i18n/translations`
  и из папки, выбранной в настройках. Встроенные каталоги остаются доступны,
  внешние могут добавлять языки и переопределять отдельные файлы.
- Исходный язык интерфейса - русский. Для остальных языков менеджер хранит
  точные строки и regex-шаблоны динамических подписей, а при отсутствии
  ключа откатывается к английскому и затем к исходной строке.
- `translate_tree()` обходит виджеты, подсказки, placeholder'ы, элементы
  списков, заголовки таблиц и QAction. Исходное значение каждого свойства
  запоминается рядом с виджетом, поэтому переключение языка не портит
  пользовательские данные.
- Язык и папка каталогов сохраняются в `appearance/language` и
  `appearance/translations_dir`; `SettingsPage` перечитывает каталоги без
  перезапуска. `MainWindow` переводит видимую страницу после асинхронных
  обновлений.

### `phoenix_gui/ui`

- `ThemeManager` применяет палитру, шрифт и QSS. Все цвета вынесены в
  `Theme.tokens`, а QSS собирается из плейсхолдеров. Пользовательские цвета
  проходят через `customize_theme`: из пяти основных оттенков выводятся
  границы, hover-состояния и контраст подписей.
- `Motion` держит один фильтр событий приложения для hover-анимаций и
  переходов страниц. Флаги движения кэшируются и обновляются только по
  сигналу настроек, чтобы не читать QSettings на каждое событие мыши.
- `ChartPanel` пробрасывает колесо мыши из matplotlib в ближайший
  `QScrollArea`, поэтому жесты не залипают над графиком.
- Логотип `nvc_logo png.png` загружается через `icons.brand_logo` и
  используется в боковой панели и как иконка приложения.
- Страницы наследуют `BasePage`/`ScrollPage` и получают `PageContext`
  (сервис, настройки, темы, конфигурация и `TranslationManager`).
- Динамические подписи страницы переводят через `BasePage.tr_text()`, а
  `MainWindow` периодически переводит видимую страницу после асинхронных
  обновлений, чтобы не терять перевод статусов и сумм.
- Долгие операции идут через `run_async`; страница показывает прогресс и
  блокирует повторный запуск.
- Таблицы построены на `SortableTable` с числовыми ключами сортировки,
  поэтому суммы и даты сортируются правильно, а не как строки. При
  автообновлении страницы монет и истории сохраняют выбранные входы, позицию
  прокрутки и текущую сортировку.
- `StoragePage` работает с тремя методами прокси: `pstore` принимает путь или
  HTTP(S)-ссылку и возвращает id графа, `pload` собирает файл по id и
  расширению, `pcancel` снимает неподтвержденные pstore-транзакции с очереди.

## Приватность

`phoenix_gui/ui/widgets/privacy.py` содержит `PrivacyManager` - менеджер
эффектов размытия. Страницы через `BasePage.protect()` регистрируют только
виджеты с финансовыми данными: значения карточек, балансы, сводки, области
таблиц и canvas графиков. Заголовки, навигация и кнопки остаются четкими.
Состояние хранится в `privacy/hidden` и применяется при запуске.

## Хранилище pstore

1. Пользователь выбирает локальный файл или вставляет прямую HTTP(S)-ссылку.
2. GUI передает источник и необязательный комментарий в `pstore`; прокси
   разбивает файл на транзакции и возвращает id всего графа, число транзакций,
   размер и якорь.
3. Для получения пользователь вводит id и расширение без точки. `pload`
   собирает файл и сохраняет его в системную папку загрузок.
4. `pcancel` удаляет только неподтвержденные pstore-транзакции и восстанавливает
   якорь. Подтвержденные данные отменить нельзя.

## Экспертная отправка

1. Пользователь отмечает UTXO на странице "Монеты" или в экспертной форме.
2. `plan_send` считает размер, комиссию и сдачу. Если сдача ниже пылевого
   порога, она добавляется к комиссии.
3. GUI вызывает `createrawtransaction` с входами, выходом получателя, сдачей
   и, при наличии, hex-комментарием для `OP_RETURN`.
4. Прокси подписывает свои P2SH-Falcon входы в `signrawtransaction`.
5. Только полностью подписанная транзакция уходит в `sendrawtransaction`.

## Почему не `getbalance`

`getbalance` учитывает неподтвержденные входы, поэтому не подходит для
показа "доступно к отправке". GUI делит UTXO на:

- доступные: подтверждены и `spendable`;
- ожидающие: подтверждены не полностью;
- незрелые: награды, которые еще нельзя тратить.

Это совпадает с логикой `group_tx.balance_summary` и объясняется в подсказках.

## Расширение прокси

Добавлен необязательный метод `listaddresses`. Если прокси старый и отвечает
`-32601`, GUI переключается на адреса, выведенные из UTXO и истории. Метод
не возвращает соль, redeem script или другие ключевые материалы.
