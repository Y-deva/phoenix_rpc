# Аудит Phoenix: журнал дефектов

Дата аудита: 18.11.2026. Ветка: `feature/privacy-mode`.

GitHub Issues в репозитории отключены: API возвращает `410 Issues has been disabled`, а включение через PATCH `has_issues` недоступно токену (`403`). Поэтому список ведётся здесь и переносится в GitHub Issues после включения раздела. Каждый пункт содержит область, серьёзность, статус и ссылки на код.

## Исправлено в этом PR

### AUD-01. pstore: отмена пакета и split не разблокировали очередь
- Серьёзность: critical.
- Причина: `pcancel` удалял только pstore-транзакции, оставляя split и anchor; повторная загрузка не могла выбрать вход. При одном UTXO split забирал единственный вход, и coinstake было не из чего собрать.
- Исправление: `pstore.py` удаляет всю pending-цепочку, подтверждённый tip-anchor сохраняется; `_build_split()` требует минимум два подтверждённых входа и объясняет это пользователю.
- Проверка: `tests/test_migration.py`, сценарии pstore в `tests/test_orphans.py`; UI-подсказка в `phoenix_gui/ui/pages/storage.py`.

### AUD-02. Принятый блок не проверялся после submitblock
- Серьёзность: critical.
- Причина: `pos_miner.py` считал `submitblock` без ошибки доказательством best chain и сразу запечатывал pstore.
- Исправление: после submitblock записываются `block_id`, `coinstake txid`, вход kernel и выбранные pstore txids; `block_verify.verify_unconfirmed_blocks()` проверяет наличие coinstake и hash канонического блока; pstore подтверждается только если все txids попали в блок. Запись ретраится, майнер останавливается при невозможности записать.
- Проверка: `tests/test_orphans.py::test_block_hash_mismatch_rolls_back`, `test_pstore_package_only_confirms_when_txids_are_in_block`.

### AUD-03. Орфан-блок оставлял фантомные UTXO pstore
- Серьёзность: high.
- Причина: старый `cleanup_orphans()` удалял только UTXO/историю по txid и не откатывал pstore-цепочку, split и spent-флаги.
- Исправление: `block_verify.rollback_unconfirmed()` удаляет coinstake-UTXO, помечает историю `orphan`, возвращает kernel-вход, удаляет запись `unconfirmed_blocks`, вызывает `reindex_pstore_after_orphan()`; парсер перематывает `last_parsed`.
- Проверка: `tests/test_orphans.py::test_orphan_rolls_back_coinstake_and_kernel`, `test_pstore_reindex_restores_pending_anchor`.

### AUD-04. pload обрезал многотранзакционные цепочки
- Серьёзность: high.
- Причина: `_fetch_chain()` останавливался на trailing `OP_0`, который является разделителем одной транзакции, а не концом всей цепочки.
- Исправление: чтение идёт по `vin` до транзакции без OP_RETURN payload; маркер `OP_0` пропускается, но не завершает обход. Удалён неиспользуемый `_has_trailing_op0`.
- Проверка: ручная проверка структуры pstore-цепочки; регрессионный тест добавляется вместе с pstore-интеграцией.

### AUD-05. Нет резервирования UTXO между send, pstore и майнером
- Серьёзность: high.
- Статус: открыто.
- Причина: параллельные операции выбирают один и тот же подтверждённый вход; одна из транзакций молча проигрывает и цепочка pstore/отправка теряется.
- План: таблица reservations с TTL, выбор входов под транзакцией, снятие резерва при отмене/подтверждении; тест на конкурентные send/pstore.

### AUD-06. Не восстанавливаются spent-флаги после эвикции мемпула и реорга
- Серьёзность: high.
- Статус: частично.
- Причина: `unlock.py` помечает вход потраченным сразу; возврат при eviction/реорге не выполняется. Для coinstake kernel возврат уже реализован в AUD-03.
- План: сверять мемпул и блоки для всех локальных транзакций, отдельный reconcile-цикл; тест на evicted send.

### AUD-07. UI не обновлял страницы после отправки
- Серьёзность: medium.
- Причина: сигнал `dataChanged` не был подключён; История/Аналитика/Хранилище и баланс обновлялись только по таймеру.
- Исправление: `MainWindow._on_data_changed()` помечает страницы stale и обновляет текущую/Обзор; сигнал подключён в `_build_pages()`.
- Проверка: `tests/test_ui.py`, ручной сценарий отправки.

### AUD-08. Sheet-окна не были модальными, конфликтовали Escape/Ctrl+Enter
- Серьёзность: medium.
- Причина: фон оставался доступен по Tab, QDialog и страница регистрировали одинаковые shortcuts, срабатывал `activatedAmbiguously`.
- Исправление: `SheetHost` отключает фон и возвращает фокус; Escape обрабатывается один раз; в диалогах shortcuts переведены на `WidgetWithChildrenShortcut`.
- Проверка: `tests/test_sheets.py`, включая блокировку фона и отмену пароля.

### AUD-09. Фильтр и сортировка адресов сбрасывались
- Серьёзность: medium.
- Причина: receive-таблица каждый refresh сортировалась по балансу; account и поиск склеивались в одну строку.
- Исправление: сохраняется sort indicator, account и query фильтруются отдельно, `filter_rows()` поддерживает AND по словам.
- Проверка: `tests/test_receive.py`, `test_receive_account_filter_after_auto_generation`.

### AUD-10. Кнопка перевода в мастере миграции активна при нулевом балансе
- Серьёзность: low.
- Причина: `_set_busy(False)` включал sweep независимо от отчёта.
- Исправление: sweep включается только при `report.balance > 0` и хотя бы одном входе.
- Проверка: `tests/test_migration.py`.

### AUD-11. Кнопки прокси не отражали состояние, лишние reconnect
- Серьёзность: medium.
- Причина: Start/Stop/Restart всегда активны; редактирование любого поля connection эмитило переподключение.
- Исправление: `set_proxy_controls()` синхронизирует кнопки; `_save_connection()` сравнивает старые и новые значения и не переподключается без изменений.
- Проверка: ручной сценарий Server Center, `tests/test_ui.py`.

### AUD-12. Журнал терял позицию при автообновлении
- Серьёзность: low.
- Причина: `setPlainText()` сбрасывал scroll и selection каждые 2 секунды.
- Исправление: при `follow` прокрутка вниз, иначе сохраняются scrollbar и QTextCursor.
- Проверка: `tests/test_logs.py`, ручной сценарий.

### AUD-13. 429 не сбрасывал flood-таймер и не учитывал Retry-After
- Серьёзность: medium.
- Причина: HTTP 429 обрабатывался как обычная ошибка; cooldown не сохранялся.
- Исправление: `RPCRateLimitedError`, thread-safe cooldown, `Retry-After` с上限, экспоненциальный backoff, cooldown не сбрасывается новым 429, сбрасывается только успехом; UI показывает понятное сообщение.
- Проверка: `tests/test_rpc.py::test_rate_limit_uses_retry_after_and_blocks_immediate_retry`.

### AUD-14. Орфан-награда показывалась подтверждённой
- Серьёзность: medium.
- Причина: `history.status` хранился, но `listtransactions` не отдавал его, а UI не знал категорию `orphan`.
- Исправление: API возвращает `status`, категория `orphan`, confirmations 0; модель и таблица показывают «Орфан» красным.
- Проверка: `tests/test_orphans.py`, ручная проверка списка операций.

### AUD-15. PasswordField: неверная подсказка и глаз
- Серьёзность: low.
- Причина: поле использовалось для пароля кошелька и WIF, но подсказка говорила только о пароле; после раскрытия tooltip оставался «Показать».
- Исправление: нейтральная подсказка «пароль или приватный ключ», корректное «Показать»/«Скрыть».
- Проверка: `tests/test_sheets.py`, визуальная проверка.

## Открыто, требует отдельного решения

### AUD-16. Слабый ключ подписи блока
- Серьёзность: high (консенсус/безопасность).
- Причина: `ecdsa_sign.py` использует фиксированный приватный ключ 1; подпись блока не аутентифицирует майнера.
- Текущая мера: verifier проверяет канонический hash и coinstake, поэтому подмена не запечатывает pstore.
- План: ключ из keychain, миграция формата заголовка, отдельное обсуждение совместимости сети.

### AUD-17. pstore: split с нулевой комиссией не попадает в мемпул
- Серьёзность: high.
- Причина: split/pstore-транзакции строятся без комиссии и рассчитаны на включение нашим же майнером; при отсутствии собственного блока они не ретранслируются.
- Текущая мера: пакет остаётся pending, отмена удаляет всю цепочку, интерфейс предупреждает.
- План: комиссия и явный статус «в очереди, не в мемпуле», либо атомарная сборка блока с резервированием.

### AUD-18. Адресация pstore-якоря не ограничена
- Серьёзность: medium.
- Причина: `_try_adopt_existing_anchor` может принять чужой/старый anchor по одному признаку подтверждённости.
- Текущая мера: tip-anchor не сбрасывается при обычном upload; reindex очищает pending.
- План: хранить identity anchor (txid/vout) и принимать только собственный подтверждённый anchor.

### AUD-19. Прокси: allowlist, Basic auth и HTTP-коды
- Серьёзность: low/security.
- Причина: generic forward пропускает любой RPC; Basic auth по HTTP; часть ошибок отдаётся с HTTP 200.
- План: allowlist методов, 4xx/5xx для ошибок, предупреждение о локальном HTTP, ограничение размера запроса.
